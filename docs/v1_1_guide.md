# PLC 监控系统 V1.1 — 原理与使用指南

> 本文档针对 **V1.1 版本**（2026-09-13 更新），重点说明 V1.1 的核心改动：数据库存储线程解耦。

---

## 一、V1.1 改了什么（核心原理）

### 1.1 V1.0 的问题

| 问题 | 影响 |
|------|------|
| 传感器数据从未写入数据库 | `历史查询`页永远是空的 |
| 报警产生/恢复直接在 GUI 线程写库+commit | 高数据量时可能卡界面 |
| `system_events` 表有结构但无数据 | 无法追溯系统行为 |

### 1.2 V1.1 的解决方案：后台存储线程

```
┌──────────────────────────────────────────────────────────┐
│  GUI 主线程 / 采集线程                                      │
│    data_ready 信号到达 → _on_data_ready()                 │
│      │ ① 更新界面（MonitorPage / TrendPage）              │
│      │ ② 推入存储队列（非阻塞，<1ms）                      │
│      │ ③ 报警判断（纯内存，不碰数据库）                    │
│      ▼                                                    │
│    queue.Queue ──► DatabaseWriterThread（独立 QThread）   │
│                        │ 批量 flush（每 4 条 / 每 2 秒）   │
│                        ▼                                   │
│                    SQLite ←── 写入 sensor_data            │
│                    SQLite ←── 写入 alarm_records          │
│                    SQLite ←── 写入 system_events          │
└──────────────────────────────────────────────────────────┘
```

**关键设计：**
- **queue.Queue**（标准库，线程安全）：采集/GUI 线程把写入操作封装成字典推入队列，**不阻塞**。
- **DatabaseWriterThread**（QThread）：在独立线程中批量执行 `INSERT`/`UPDATE`/`COMMIT`，**不干扰 GUI 刷新**。
- **批量写入**：每攒够 4 条或每 2 秒 flush 一次，减少磁盘 IO。

### 1.3 新旧架构对比

| 维度 | V1.0 | V1.1 |
|------|------|------|
| 传感器数据入库 | ❌ 从未写入 | ✅ 每次采集都入队 |
| 报警持久化 | 同步写库，阻塞 GUI | 异步入队，零阻塞 |
| 系统事件记录 | 无 | 启动/关闭/通信异常自动记录 |
| 历史查询 | 永远空表 | 可查真实历史数据 |
| 高负载表现 | 可能卡界面 | 队列缓冲，界面流畅 |

## 二、启动流程（和 V1.0 相同）

### 2.1 环境要求
- Python 3.11 ~ 3.12（推荐）
- Windows 10/11

### 2.2 安装依赖
```bash
cd plc-monitor-sim
pip install -r requirements.txt
```

### 2.3 启动模拟器（虚拟 PLC）

在**第一个终端**：
```bash
python -m app.simulator.main
```

输出：
```
[Modbus Server] 已启动于 127.0.0.1:5020 (slave_id=1)
>>> [自动演示] 启动设备
按 Ctrl+C 停止模拟器。
```

### 2.4 启动上位机监控软件

在**第二个终端**：
```bash
python -m app.gui.main_window
```

启动时会自动：
1. 启动 `DatabaseWriterThread`（后台存储线程）
2. 初始化 SQLite 表结构（`data/monitor.db`）
3. 启动 `AcquisitionWorker`（500ms 周期采集）
4. 记录系统事件：`上位机监控软件启动`

## 三、各页面功能与使用

### 3.1 实时监控
- **大字体显示**：温度、压力、转速、电流、电压
- **状态灯**：运行（绿）、故障（红）、启动中（黄）
- **通信状态**：OK（绿）/ ERROR（红）/ DISCONNECTED（灰）
- **报警文本**：当前活动报警实时显示

### 3.2 趋势曲线
- 温度 / 压力 / 转速 三条实时曲线
- 可勾选显隐
- 环形缓冲 500 点（约 4 分钟历史）

### 3.3 报警记录
- **当前活动报警**：红色标识，可点击"确认"
- **报警历史**：已恢复 / 已确认的报警记录
- 报警等级颜色：**ALARM = 红底白字，WARNING = 黄底**

### 3.4 历史查询（V1.1 现在有真实数据了）
- **时间范围选择**：开始时间 ~ 结束时间
- **查询结果表格**：显示该时间段内的所有传感器数据
- **导出 CSV**：将查询结果保存为 CSV 文件（默认保存到桌面）

> **注意**：历史数据来自 `DatabaseWriterThread` 批量写入的 `sensor_data` 表，程序运行一段时间后才有数据可查。

### 3.5 设备控制
- **启动设备**：向虚拟 PLC 发送 START 命令
- **停止设备**：发送 STOP 命令
- **设定转速**：0 ~ 1500 RPM（运行中生效）
- **注入故障**：模拟设备故障（转速滑落，报警触发）
- **清除故障**：恢复设备正常状态

## 四、系统事件日志（V1.1 新增）

系统自动记录以下事件到 `system_events` 表：

| 事件 | 类型 | 触发时机 |
|------|------|----------|
| 上位机启动 | INFO | 程序启动时 |
| 用户关闭程序 | INFO | 点击窗口关闭按钮确认后 |
| 通信异常 | WARNING | Modbus 连续心跳不变或连接断开 |
| 报警产生 | 通过 alarm_records 表 | 阈值超过时 |
| 报警恢复 | 通过 alarm_records 表 | 数值回落到迟滞边界以下 |
| 报警确认 | 通过 alarm_records 表 | 用户点击确认按钮 |

## 六、常见问题

**Q：历史查询页没有数据？**
> A：程序刚启动时数据库为空，需要运行一段时间后（至少几秒，采集线程 500ms 周期写入），再打开历史查询页选择时间范围查询。

**Q：退出程序时数据会丢失吗？**
> A：不会。`closeEvent` 会先将退出事件推入存储队列，然后调用 `DatabaseWriterThread.stop()`，该函数会等待队列中的剩余数据全部 flush 到数据库后再关闭线程。

**Q：报警确认后数据库会更新吗？**
> A：会。点击"确认"按钮后，`AlarmPage` 发射 `alarm_acknowledged` 信号，`MainWindow` 接收后将确认操作推入存储队列，异步更新 `alarm_records` 表的 `acknowledged` 和 `acknowledged_at` 字段。
