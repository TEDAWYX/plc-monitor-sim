# PLC 工业数据采集与监控仿真系统 —— 用户手册

> **版本**: V1.0  
> **日期**: 2026-09-11  
> **适用对象**: 本科工程实践、工业自动化学习

---

## 1. 系统简介

本系统是一个运行在 Windows PC 上的工业自动化监控软件仿真系统。它模拟了一个虚拟的工业设备（如电机驱动系统），并通过 Modbus TCP 协议进行数据通信，实现数据采集、实时监控、报警检测、历史查询等功能。

**重要说明**：
- 本系统**不连接真实 PLC 硬件**，所有数据均为软件仿真产生
- 物理模型为简化模型，用于产生具有工业过程特征的仿真数据
- 不代表任何真实设备的精确动力学模型

---

## 2. 系统架构

系统由两个独立进程组成：

### 2.1 虚拟设备模拟器（进程 1）

- 模拟工业设备的运行状态（温度、压力、转速、电流、电压等）
- 通过 Modbus TCP Server 对外提供数据
- 默认监听 `127.0.0.1:5020`
- 可独立运行

### 2.2 上位机监控软件（进程 2）

- PySide6 开发的桌面 GUI 应用
- 作为 Modbus TCP Client 连接模拟器
- 实现数据展示、趋势曲线、报警、控制等功能

## 3. 安装与运行

### 3.1 环境要求

- **操作系统**: Windows 10/11
- **Python**: 3.11 ~ 3.12（推荐）
- **注意**: Python 3.13+ 可能遇到 PySide6 兼容性问题

### 3.2 安装步骤

1. 解压项目文件到任意目录
2. 打开命令提示符（CMD）或 PowerShell
3. 进入项目目录：
   ```bash
   cd plc-monitor-sim
   ```
4. 安装依赖：
   ```bash
   pip install -r requirements.txt
   ```

### 3.3 启动系统

**步骤 1：启动模拟器**

打开第一个终端窗口，执行：
```bash
python -m app.simulator.main
```

看到以下输出表示启动成功：
```
[Modbus Server] 已启动于 127.0.0.1:5020 (slave_id=1)
>>> [自动演示] 启动设备
按 Ctrl+C 停止模拟器。
```

**步骤 2：启动上位机**

打开第二个终端窗口，执行：
```bash
python -m app.gui.main_window
```

或：
```bash
python app/gui/main_window.py
```

上位机窗口将自动打开，开始显示实时数据。

## 4. 功能说明

### 4.1 实时监控页面

显示当前设备的各项传感器数据：

| 数据项 | 单位 | 正常范围 | 说明 |
|--------|------|----------|------|
| 温度 | ℃ | 25 ~ 80 | 设备运行温度 |
| 压力 | kPa | 300 ~ 450 | 系统压力 |
| 电机转速 | RPM | 0 ~ 1500 | 电机当前转速 |
| 电流 | A | 0 ~ 25 | 电机电流 |
| 电压 | V | 340 ~ 420 | 供电电压 |

**状态指示灯**：
- **运行状态**：绿色=运行中，黄色=启动中，灰色=停止，红色=故障
- **故障状态**：灰色=无故障，红色=有故障
- **通信状态**：绿色=正常，红色=异常，灰色=未连接

**报警信息**：显示当前活动报警（如有）。

### 4.2 趋势曲线页面

显示温度、压力、电机转速的实时变化曲线：

- **时间轴**：相对时间（秒）
- **曲线颜色**：温度=红色，压力=蓝色，转速=绿色
- **显隐控制**：通过复选框选择显示/隐藏某条曲线
- **数据缓冲**：默认保留最近 500 个数据点（约 4 分钟）

### 4.3 报警记录页面

显示报警信息：

**当前活动报警**：
- 时间、报警类型、报警值、等级
- 操作列提供"确认"按钮

**报警历史**：
- 显示所有报警记录（包括已恢复的）
- 状态列显示 ACTIVE（红色）或 RECOVERED（绿色）

**按钮**：
- **刷新**：手动刷新报警显示
- **清空历史**：清空所有报警记录

### 4.4 历史查询页面

查询和导出历史数据：

**查询条件**：
- 开始时间、结束时间（通过日历控件选择）

**操作**：
- **查询**：按时间范围查询 sensor_data
- **导出 CSV**：将查询结果导出为 CSV 文件

**导出文件**：
- 默认保存到桌面
- 文件名格式：`industrial_monitor_data_YYYYMMDD_HHMMSS.csv`
- 编码：UTF-8 with BOM（兼容 Excel）

### 4.5 设备控制页面

控制虚拟设备的运行：

**启停控制**：
- **启动设备**（绿色按钮）：设备进入启动过程
- **停止设备**（红色按钮）：设备进入停机过程

**目标转速设定**：
- 输入范围：0 ~ 1500 RPM
- 点击"设定转速"生效

**故障模拟**：
- **注入故障**（黄色按钮）：模拟设备故障状态
- **清除故障**：清除故障，设备回到停止状态

**注意**：所有控制操作均有确认提示，防止误操作。

## 5. 报警说明

### 5.1 报警类型

| 报警类型 | 警告阈值 | 报警阈值 | 迟滞 |
|----------|----------|----------|------|
| 温度高 | > 75℃ | > 80℃ | 2℃ |
| 压力高 | > 450 kPa | > 520 kPa | 5 kPa |
| 压力低 | < 300 kPa | < 280 kPa | 5 kPa |
| 电流高 | > 20 A | > 25 A | 1 A |
| 电压高 | > 400 V | > 420 V | 2 V |
| 电压低 | < 360 V | < 340 V | 2 V |
| 转速低 | — | < 100 RPM | 10 RPM |

### 5.2 报警状态

- **ACTIVE**：报警活动中，数值超过阈值
- **RECOVERED**：报警已恢复，数值回落到恢复阈值以下
- **ACKNOWLEDGED**：报警已人工确认

### 5.3 迟滞机制

为避免数值在阈值附近波动导致报警频繁切换：
- **产生报警**：数值超过报警阈值
- **恢复报警**：数值回落到（报警阈值 - 迟滞量）以下

例如：温度报警阈值 80℃，迟滞 2℃：
- 80.1℃ → 产生报警
- 79.0℃ → 报警仍活动（未低于 78℃）
- 77.0℃ → 报警恢复

## 6. 典型操作流程

### 6.1 正常启停流程

1. 启动模拟器（终端 1）
2. 启动上位机（终端 2）
3. 在"实时监控"页观察初始状态（停止）
4. 切换到"设备控制"页，点击"启动设备"
5. 观察"实时监控"页：
   - 运行状态灯变黄色（启动中）
   - 转速逐渐上升
   - 温度逐渐上升
   - 运行状态灯变绿色（运行中）
6. 切换到"趋势曲线"页，观察变化趋势
7. 回到"设备控制"页，点击"停止设备"
8. 观察转速下降、温度回落

### 6.2 故障模拟流程

1. 确保设备处于运行状态
2. 在"设备控制"页点击"注入故障"
3. 观察"实时监控"页：
   - 运行状态灯变红色
   - 故障状态灯变红色
   - 转速快速跌落
   - 温度异常升高
4. 切换到"报警记录"页，查看报警信息
5. 点击"确认"按钮确认报警
6. 在"设备控制"页点击"清除故障"
7. 设备回到停止状态

### 6.3 数据导出流程

1. 运行系统一段时间，积累历史数据
2. 切换到"历史查询"页
3. 选择开始时间和结束时间
4. 点击"查询"按钮
5. 查看查询结果表格
6. 点击"导出 CSV"按钮
7. 选择保存路径（默认桌面）
8. 使用 Excel 打开导出的 CSV 文件

## 7. 常见问题

### Q1: 启动上位机时提示"Modbus 客户端未初始化"

**A**: 请确保模拟器已先启动。上位机需要在模拟器启动后才能正常连接。

### Q2: 通信状态显示"未连接"

**A**: 
1. 检查模拟器是否已启动
2. 检查防火墙是否阻止了 5020 端口
3. 检查 `app/config/settings.py` 中的 `modbus.host` 和 `modbus.port` 配置

### Q3: 趋势曲线没有数据

**A**: 
1. 检查通信状态是否为"正常"
2. 检查"趋势曲线"页的复选框是否已勾选
3. 等待几秒钟，数据会逐步积累显示

### Q4: 报警没有触发

**A**: 
1. 检查设备是否处于运行状态（报警只在运行中检测）
2. 检查报警阈值配置（`app/config/settings.py`）
3. 尝试注入故障测试报警系统

### Q5: 如何修改报警阈值？

**A**: 
1. 编辑 `app/config/settings.py` 中的 `DEFAULT_CONFIG["alarms"]`
2. 或在 `app/config/` 目录下创建 `settings.json` 覆盖默认值
3. 重启上位机生效

### Q6: 如何修改采集周期？

**A**: 
1. 编辑 `app/config/settings.py` 中的 `DEFAULT_CONFIG["acquisition"]["period_ms"]`
2. 或在 `settings.json` 中设置 `"acquisition": {"period_ms": 1000}`
3. 重启上位机生效

## 8. 配置文件

### 8.1 默认配置位置

`app/config/settings.py` 中的 `DEFAULT_CONFIG` 字典。

### 8.2 自定义配置

在 `app/config/settings.json` 中写入需要覆盖的配置项：

```json
{
  "modbus": {
    "port": 5020
  },
  "acquisition": {
    "period_ms": 1000
  },
  "alarms": {
    "temperature": {
      "warning_high": 70.0,
      "alarm_high": 75.0,
      "hysteresis": 3.0
    }
  },
  "gui": {
    "trend_max_points": 1000
  }
}
```

配置会自动合并，缺失项使用默认值。

## 10. 故障排除

### 10.1 模拟器无法启动

**现象**: 执行 `python -m app.simulator.main` 报错

**解决**:
1. 检查 Python 版本：`python --version`（需 3.11+）
2. 检查 pymodbus 是否安装：`pip list | findstr pymodbus`
3. 检查端口是否被占用：`netstat -ano | findstr 5020`

### 10.2 上位机界面无法打开

**现象**: 执行 GUI 启动命令后无窗口出现

**解决**:
1. 检查 PySide6 是否安装：`pip list | findstr PySide6`
2. 检查是否有图形界面环境（远程服务器可能无 GUI）
3. 尝试控制台验证：`python -m app.main`

### 10.3 测试失败

**现象**: `pytest` 运行后有测试失败

**解决**:
1. 检查所有依赖是否安装：`pip install -r requirements.txt`
2. 检查是否有其他程序占用测试端口（15020, 15050）
3. 单独运行失败测试查看详细错误

## 11. 安全注意事项

1. **本系统为仿真软件**，不控制任何真实设备
2. 故障注入功能仅影响虚拟设备模型，无实际危险
3. 数据库文件存储在本地，不含敏感信息
4. 建议定期清理 `data/monitor.db` 防止文件过大
